## D1 — risk limits must be finite (ALREADY APPLIED by the lead to the locked aegis/config.py + tests/test_config.py)
`RiskLimits` and `AutoExecuteConfig` now have `allow_inf_nan=False`: a `.inf` / `.nan` in config.yaml would silently switch a limit off, so both are refused at load. Consequence: `RiskLimits(max_loss_per_trade=float("inf"))` etc. now raises a pydantic ValidationError, and these 8 tests fail and must be updated (do not weaken what they prove — replace the infinite/NaN limit with the largest finite value, e.g. `sys.float_info.max`, and keep every other hostile input):
- tests/test_policy_engine.py::TestEvilCases::test_a_naked_short_call_whatever_the_loss_cap_says[inf]
- tests/test_policy_engine.py::TestEvilCases::test_a_naked_short_call_is_rejected_by_options_max_loss_on_its_own
- tests/test_policy_limits.py::TestHostileButValidContexts::test_the_report_never_raises
- tests/test_policy_rules.py::TestDailyLossLimit::test_an_unrepresentable_fallback_halts_to_the_end_of_the_calendar[inf]
- tests/test_policy_rules.py::TestOptionsMaxLoss::test_unlimited_risk_rejects_whatever_the_cap_says[inf]
- tests/test_policy_rules.py::TestHostileButValidInputs::test_zero_limits
- tests/test_policy_rules.py::TestHostileButValidInputs::test_limits_too_large_to_print_or_to_be_a_duration
- tests/test_policy_rules.py::TestHostileButValidInputs::test_no_rule_raises_for_any_hostile_pair
Any generator of random/hostile limits (tests/policy_factories.py, the randomized engine test, the limits sweep, the CLI sweeps) must stay inside what RiskLimits accepts (finite numbers) — but must still reach the extremes that ARE accepted (0, sys.float_info.max, very large ints). Code in aegis/policy that handled an infinite LIMIT (not an infinite notional — that one stays) may be simplified only if it is provably unreachable; when in doubt leave the guard.

## D2 — a proposal's shape must be consistent, and `structure_problems` is where that is judged
Found by the lead and by the context stage: (i) nothing in the rules compares a leg's `symbol` with the contract the leg describes (context.py's `_contract_problems` catches it only for contexts built by `build_context`); (ii) nothing rejects a proposal declared `equity` whose symbol is an OCC option symbol, or that carries option legs — with a quote in hand its notional is computed WITHOUT the contract multiplier and it could reach AUTO_EXECUTE as if it were shares. The gate must not rely on the brain being well-behaved.
- `measures.structure_problems(proposal)` becomes the single judge of shape, for BOTH instruments (it is no longer "always empty for an equity"):
  - an OPTION proposal: the existing findings (no legs; legs on more than one underlying; the proposal symbol's underlying differs from the legs'; legs with different expirations; a non-whole leg quantity), plus: each leg's `symbol` must be an OCC option symbol whose root, expiration, option type and strike are the leg's own `expiration`, `option_type`, `strike` and underlying (strike compared with the float-noise guard) — move the logic of `context._contract_problems` here and delete it there; and when the proposal's OWN symbol is an OCC option symbol it must be the symbol of its only leg (a multi-leg structure is named by its underlying).
  - an EQUITY proposal: "an equity proposal carries N option leg(s)" when it has legs; "the proposal is declared equity but its symbol <S> is an option contract" when its symbol is an OCC option symbol.
- New measure `is_plain_equity(proposal) -> bool`: instrument equity, no legs, symbol not an OCC option symbol.
- `options_max_loss` calls `structure_problems` FIRST, for every proposal: any finding → REJECT ("the structure cannot be analysed: …" / for an equity "the proposal is not a plain equity: …"). A plain equity → PASS "not an option". Then the option path as today.
- `options_escalate`: ESCALATE unless `is_plain_equity(proposal)` — anything option-like always needs a human. `auto_tier`: the criterion "the instrument is equity" becomes `is_plain_equity(proposal)`. (So three independent rules stand between a mislabelled option and AUTO_EXECUTE.)
- `options_min_dte` / `options_max_contracts`: unchanged for options; for a proposal declared equity that carries legs they keep returning PASS "not an option" (options_max_loss owns that rejection) — do not invent further behaviour.
- `notional` is unchanged.
- `context.structure_analysis` / `_analyse` rely on `measures.structure_problems` alone (no second check), keep returning None with the reasons joined in `errors`.
- Tests: every new finding, each on its own (a leg whose symbol is the 700 call while the leg says 660; a put symbol on a call leg; a wrong expiration; a wrong root; a non-OCC leg symbol; an OCC proposal symbol that is not its leg's; an OCC proposal symbol with two legs; an equity with legs; an equity whose symbol is an OCC contract) → `options_max_loss` REJECT with the finding in the detail, `options_escalate` ESCALATE, `auto_tier` ESCALATE; and the governance case end to end through the engine: an otherwise perfect auto-tier buy whose symbol is `SPY260821C00640000` declared equity, with a two-sided quote for that symbol in the context → REJECT (failing_rule options_max_loss), never AUTO_EXECUTE. Add these shapes to the randomized generators. The brain's real proposals (single-leg with the OCC symbol or the underlying as the proposal symbol; multi-leg named by the underlying) must still pass `structure_problems` — test both.

## D3 — the Executor rule's runtime backstop must survive Phase 6
Today tests/test_policy_architecture.py's PART 1 backstop imports every module outside aegis/policy and aegis/execution and asserts no `aegis.execution*` module is loaded afterwards. In Phase 6 `aegis.policy` will legitimately import the Executor at module level, and then importing `aegis.cli.policy` (outside, but it imports the policy package) loads it transitively and the backstop would fail for the wrong reason. Make the invariant precise NOW: in the fresh interpreter, attribute every import of `aegis.execution` (and submodules) to the module that asked for it — the nearest calling frame, outside the import machinery, whose `__name__` starts with `aegis.` — and assert every such importer is under `aegis.policy` or `aegis.execution`. Today the set of importers is empty; keep asserting that it is a subset of the two packages (not that it is empty). Prove the harness on toy trees: (a) an outside module that imports the execution package directly → caught, naming that module; (b) an outside module that imports a policy module which itself imports the execution package → allowed; (c) a lazy import inside a function of an outside module, called during the run → caught. The static rules of PART 1 are unchanged.
